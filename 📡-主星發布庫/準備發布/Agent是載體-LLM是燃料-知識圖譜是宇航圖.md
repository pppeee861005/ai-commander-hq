# Agent 是載體，LLM 是燃料，知識圖譜是宇航圖

## 【Mythos 敘事層】開場

2026 年，我們終於不再問「AI 能做什麼」，而是問「我們要去哪裡」。

三年前，我們看著 ChatGPT 震驚。兩年前，我們看著 Claude 驚艷。去年，我們開始用 Agent 改變工作方式。今年，我們發現了一個隱喻，它解釋了為什麼 LLM 再強也需要 Agent；為什麼 Agent 再聰慧也需要知識圖譜。

**比喻很簡單：**
- **LLM 是燃料**：能量、思考、語言模型的生成能力
- **Agent 是載體**：結構、編排、決策與執行的框架
- **知識圖譜是宇航圖**：座標系、星圖、告訴我們「現在在哪」和「要去哪」的永恆記錄

沒有燃料，火箭不會起飛。沒有載體，燃料就是爆炸。沒有宇航圖，我們只會漂流在無邊的虛空。

## 【Logos 知識層】三個系統的本質

### 1. LLM = 燃料的三個面向

**首先，LLM 是能量。**

當你問 Claude 一個問題，你在消耗的不是計算，而是一個龐大的「意義空間」被激活。LLM 的本質是：將人類語言的意圖，轉化為概率分佈上的路徑選擇。

- 它有 **無限的表達潛能**（燃料可以燃燒成任何溫度）
- 但它 **沒有方向性**（燃料只會往下燒）
- 它 **不記得** 任何東西（每次對話都從零開始）

這就是為什麼純 LLM 的產品總是「很智能但不可靠」。ChatGPT 可以和你聊莎士比亞，但它無法記住你昨天要什麼。Claude 可以幫你寫複雜的代碼，但它無法保證代碼的連貫性。

**LLM 是完美的一次性火焰。**

### 2. Agent = 載體的三個結構

**Agent 解決的是編排問題。**

Agent 不是「更聰明的 LLM」。Agent 是一個 **決策循環**：
```
感知 → LLM 推理 → 工具調用 → 狀態更新 → 反饋 → 下一步決策
```

我們在圖譜中發現的 **Hermes Agent**、**UR-Navigator Agent** 都遵循這個模式。它們的本質不是智能，而是 **持久性**。

- Agent 記住了 **上下文**（我剛才做了什麼）
- Agent 維護了 **狀態**（系統現在在哪個環節）
- Agent 執行 **反饋迴圈**（這次的結果改變了下一次的決策）

**LLM 是瞬間的智慧。Agent 是累積的智慧。**

### 3. 知識圖譜 = 宇航圖的三層意義

**知識圖譜解決的是永恆的問題：「這一切是如何連接的？」**

在我們的系統中，知識圖譜不是 RAG 的替代品，而是 **Agent 的大腦**。

它記錄：
- **節點**：每一個概念、工具、文檔、決策
- **邊**：它們之間的 **因果、引用、相似、包含** 關係
- **社群**：相似節點聚集的區域，代表 **問題域**

當我用 `/graphify query` 查詢「Agent 和 LLM 如何互動」時，它不是搜索（Google 會做的）；它是 **路徑追蹤**——沿著圖的邊走，發現隱藏的連接。

**知識圖譜是系統的 GPS。它告訴你「你在星圖上的座標」。**

## 【Sigma 科學層】為什麼需要三層？

### 能量 → 結構 → 導航的必然性

想像一個火箭：
- 沒有燃料？ → 靜止
- 有燃料但沒有結構？ → 爆炸
- 有燃料和結構但沒有導航？ → 亂飛

**現在的 AI 產業正處於這個階段的演進。**

#### Phase 1（2023）：人們驚訝於 LLM 的能力
- 「ChatGPT 能寫詩！」
- 「Claude 能編代碼！」
- 但每次都是獨立的、一次性的

#### Phase 2（2024）：Agent 框架開始普及
- AutoGPT、LangChain、LlamaIndex
- Agent 可以調用工具、記住狀態
- 但仍然是「局部的」——每個 Agent 是孤島

#### Phase 3（2025-2026）：知識圖譜成為中樞神經系統
- 圖譜連接所有 Agent
- 圖譜記錄所有決策
- 圖譜指導未來的行動

### 從我們的系統中看

我們的圖譜中有 **287 個節點、421 條邊、24 個社群**。

其中最高度的節點是：

2. **Software 3.0 的散戶基礎設施**（19 連接）— 具體應用
3. **Agent 能力基線快照**（19 連接）— Agent 的標準化描述

為什麼 Agent 能力基線會有 19 條邊？因為它不是孤立的概念。它連接到：
- **Hermes Agent**（實現它的工具）

**沒有圖譜，這些連接是看不見的。**

## 【Sigma 科學層 - 深化版】系統演進的三個引擎

### 三大技術支柱

#### 引擎 1：LLM 的三個能力邊界

在現有框架中，LLM 暴露出的三個根本限制，Agent 必須補償：

**限制 1：Token 記憶窗口**
- Claude 3.5 的上下文長度：200K tokens（約 150 萬字）
- 但實際有效記憶：前 10K 和後 20K tokens（「注意力崖」現象）
- 解決方案：Agent 的持久記憶層（數據庫）和檢索增強（RAG）

**限制 2：推理的一致性漂移**
- LLM 在長對話中會「遺忘前提」
- 同一問題的答案在 10 輪後可能自相矛盾
- 解決方案：Agent 的「狀態機」——每次決策都檢查上一次的結論

**限制 3：無法驗證自己**
- LLM 會自信地說出錯的答案（幻覺）
- 無法判斷「我確定」vs「我猜測」
- 解決方案：Agent 的「工具驗證環節」——每個輸出都需要外部系統確認

在新人類聯盟中：
- **Claude** 扮演「無限想像力」但「需要監督」的角色
- **Hermes Agent** 扮演「持久記憶」和「決策驗證」的角色
- **知識圖譜** 扮演「事實檢查員」和「記錄者」的角色

#### 引擎 2：Agent 的三層編排結構

我們在圖譜中發現的 Agent 實現有一個統一的 DNA：

```
L1 Agents（決策層）
  ↓ 調用 ↓
L2 Agents（協調層）
  ↓ 調用 ↓
L3 Agents（執行層 / Skills）
```

**L1 - 決策層**（戰略性）
- 例：UR-Navigator Agent 看到「台北新建案需要都更評估」
- 決策：呼叫哪個 L2 agent？用什麼參數？
- 記錄：這個決策被加入圖譜

**L2 - 協調層**（執行性）
- 例：「都更評估 Coordinator」收到決策
- 協調：同時調用「法規查詢」、「財務計算」、「進度追蹤」三個 L3
- 記錄：子任務的狀態和依賴關係

**L3 - 執行層**（原子性）
- 例：「法規查詢 Skill」呼叫 GraphQL 查詢知識圖譜
- 執行：取回相關法規節點
- 反饋：結果和執行時間回傳到 L2

**為什麼三層？**
- 一層太簡單（退化成序列調用）
- 兩層無法表達複雜的協作模式
- 三層達到了「樹形編排的最小複雜度」

在 Software 3.0 的散戶基礎設施中：
```
L1: 「幫用戶發現交易機會」
  └─→ L2: 「行情分析協調」
        ├─→ L3: 行情實時拉取（Futu API）
        ├─→ L3: 技術面掃描（ta-lib）
        └─→ L3: 輿情監控（新聞 API）
  └─→ L2: 「風險評估協調」
        ├─→ L3: 資金容量檢查
        ├─→ L3: 歷史回測
        └─→ L3: 監管檢查
```

#### 引擎 3：知識圖譜的三種邊

不是所有的「連接」都一樣。圖譜中的邊有三個層次：

**EXTRACTED 邊（確定性）** - confidence_score = 1.0
- 源代碼中的實際導入：`import Agent from tools`
- 文件中的明確引用：「見《Agentic 四柱》」
- 調用關係：Hermes Agent → NotebookLM API
- 代表：「這個連接肯定存在」

**INFERRED 邊（概率性）** - confidence_score 0.55-0.95
- Software 3.0 和龍蝦社團的連接（0.85）：同一篇文章，相同受眾
- Agent 能力基線和新人類聯盟（0.90）：概念上的相承
- 代表：「這個連接很可能存在」

**AMBIGUOUS 邊（待驗證）** - confidence_score 0.1-0.3
- 某個決策和最終成果的因果關係（0.25）：有關聯但無直接證據
- 代表：「這個連接可能存在，但需要時間驗證」

**為什麼要分類？**
這是 graphify 比傳統 RAG 強大之處：
- 傳統 RAG：有連接 = 1，沒有 = 0（二進制）
- graphify：有 0.55（弱）、0.85（強）、1.0（確定）的梯度

當 Agent 查詢「應該參考哪個過去的成功案例」時：
- 它看到 Software 3.0 → 龍蝦社團（0.85）
- 它看到 Software 3.0 → Hermes Agent（0.90）
- 它看到 Software 3.0 → 新人類聯盟（1.0）
- Agent 會優先選擇 confidence_score 最高的決策路徑

### 三層的演化趨勢

從工業演進的角度：

| 時代 | LLM 角色 | Agent 角色 | 圖譜角色 | 范例 |
|------|---------|----------|---------|------|
| 2.0 時代（2022） | 文本生成 | 無 | 無 | ChatGPT |
| 2.5 時代（2023） | 推理 + 生成 | 工具調用 | 無 | GPT-4 with tools |
| 3.0 時代（2024） | 思考 | 決策迴圈 | 檢索（RAG） | LangChain Agent |
| 3.5 時代（2025-2026） | 預測 | 多層編排 | **永恆記憶** | 新人類聯盟模型 |

我們現在在 3.5 時代的起點。
