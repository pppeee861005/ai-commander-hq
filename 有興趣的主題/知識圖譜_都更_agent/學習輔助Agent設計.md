## 🧠 Agent 的核心能力（4 項）

### 能力 1️⃣：查詢你的知識圖譜
**工作原理**：
```
你問：「Agent 和 Hermes 的關係是什麼？」
   ↓
Agent 執行：/graphify query "Agent 和 Hermes"
   ↓
返回：Agent 節點 + Hermes 節點 + 它們之間的連接
   ↓
Agent 用人話解釋：「Hermes 是一個具體的 Agent 實現，
                  它實現了軟件 3.0 的思想，
                  和 agentic_new_city 都是 AI 大腦協調的例子」
```

### 能力 2️⃣：識別知識缺口
**工作原理**：
```
你說：「我還是不太懂 Agent 怎樣用 graphify」
   ↓
Agent 分析：你已經知道「知識圖譜」的概念
           你知道「都市更新」的複雜性
           但你不理解「Agent 怎樣查詢圖譜」
   ↓
Agent 建議：「我先給你看一個具體例子：
            如果你是都市更新的協調 Agent，
            怎樣用 graphify 回答『現在進度多少』這個問題」
```

### 能力 3️⃣：用對比法講解
**工作原理**：
```
你問：「知識圖譜比傳統的 Excel 表格好在哪裡？」
   ↓
Agent 返回：
  ✗ Excel 表格
    - 行列固定
    - 難以表達複雜關係
    - 更新時容易出錯

  ✓ 知識圖譜
    - 節點 = 概念，邊 = 關係
    - 一個節點可以有無限多個連接
    - 新發現會自動補充

  🎯 例子：成本分配
    - Excel：A 列=地主名字，B 列=應付款，C 列=已付款
    - 圖譜：地主節點 --貢獻--> 財務節點 --支付--> 銀行節點
           還能追蹤「為什麼是這個數字」（依據節點）
```

### 能力 4️⃣：生成 Agent 練習題
**工作原理**：
```
Agent 給你具體的練習：

題目 1：「如果你要設計一個『都市更新風險預警 Agent』，
       它應該監控知識圖譜的哪些部分？」

參考答案：
  - 風險圖譜（已知風險）
  - 進度圖譜（延誤風險）
  - 財務圖譜（資金短缺風險）
  - 角色圖譜（關鍵人物離職風險）

你的答案：___________

Agent 反饋：「你很接近！還要加上『決策圖譜』，
           因為有些決定會觸發新的風險」
```

## 📚 Agent 會教你的 5 個核心概念

### 概念 1：節點 = 概念，邊 = 關係

**Agent 會問你**：
- 「都市更新中，誰是『節點』？」
  - 答案：政府、地主、建商、銀行、律師...
- 「他們之間的『邊』是什麼？」
  - 答案：簽約、支付、協商、決策...

### 概念 2：圖譜的自動化查詢

**Agent 會演示**：
```
場景 1：「地主問『為什麼共同負擔這麼多？』」
  Agent 執行：/graphify path "地主" "共同負擔"
  結果：顯示完整推理路徑
        地主 → 房產評估 → 建築成本 → 共同負擔

場景 2：「政府問『進度為什麼延誤』」
  Agent 執行：/graphify query "進度圖譜 瓶頸"
  結果：自動識別：融資、地政士簽核、...

場景 3：「建商問『有沒有類似案例』」
  Agent 執行：/graphify query "案例圖譜 相似"
  結果：列出 3-5 個類似項目 + 他們的成本、時間
```

### 概念 3：信息不對稱 → 衝突

**Agent 會點出**：
```
傳統情況：
- 政府知道法規進度
- 地主不知道
- 建商知道融資狀況
- 居民不知道
  → 互不信任、反覆協商、延誤

用知識圖譜：
- 所有人看同一個進度圖譜
- 政府更新 → 地主自動看到
- 分歧立刻看出來（不是被隱藏）
  → 有數據的協商、快速達成共識
```

### 概念 4：Agent 怎樣做決策

**Agent 會帶你走一遍流程**：
```
決策流程：「要不要批准這個變更設計？」

Step 1：查法規圖譜
  新設計是否違反法規？✓ 合規

Step 2：查進度圖譜
  現在施工進度多少？ 60% 完成
  改設計會延誤多久？ 3 個月

Step 3：查財務圖譜
  改設計增加成本多少？ 200 萬
  誰來付這 200 萬？（檢查資金來源）

Step 4：查決策圖譜
  過去類似變更怎麼決定的？
  都是誰同意的？

Step 5：查角色圖譜
  需要誰簽核？
  有沒有人可能反對？

Step 6：生成建議
  「我建議不要改，因為：
   - 延誤成本 > 設計收益
   - 地主和建商都會虧
   - 政府審批時間翻倍」
```

### 概念 5：持續學習 = 圖譜動態更新

**Agent 會展示**：
```
第一週：你知道「進度圖譜」有 5 個里程碑

一個月後：實際執行發現有 3 個隱藏的里程碑
         （簽合約、銀行放款、地政士複核）

Agent 自動：/graphify --update
           重新提取文件
           發現新的節點和邊
           更新進度圖譜

你再問進度時：Agent 給你的答案精確度 ↑
             因為圖譜變得更真實
```

## 🛠️ 實作：你會親手做的 3 件事

### 練習 1：為都市更新建立「簡化圖譜」（第 1-2 週）

**目標**：手動創建 5 個關鍵節點 + 它們的關係

```
節點：
  1. 地主
  2. 建商
  3. 政府
  4. 施工進度
  5. 成本

關係：
  地主 --簽約--> 建商
  建商 --申請--> 政府
  政府 --批准--> 施工進度
  施工進度 --支付--> 成本
  ...
```

Agent 反饋：「你的圖譜缺少什麼？」

**可能的缺漏**：
- 銀行（融資）
- 律師（法律檢查）
- 承包商（施工方）
- 監理單位（進度確認）

**深化版**：加上這些節點，你的決策會更全面

### 練習 2：用 graphify 查詢你自己的文件（第 3-4 週）

**步驟**：
1. 收集 3-5 份真實的都市更新文件
   - 合約、進度報告、成本預算、法律意見書

2. 執行：`/graphify 你的文件夾 --mode deep`
   - Agent 幫你自動提取
   - 你看實際結果

3. 提問：「這個合約和法律意見書的關係是什麼？」
   - Agent 查圖譜回答
   - 你驗證答案是否正確

4. 改進：「圖譜漏掉了什麼？」
   - 你補充人工標註
   - 重新執行 `--update`

### 練習 3：設計一個 Agent 的決策流程（第 5-8 週）

**選一個真實的都市更新問題**：
- 「我的建案該選自辦還是委開？」
- 「共同負擔合理嗎？」
- 「現在有沒有資金風險？」

**設計 Agent 的思路**：
```
問題：我的建案該選自辦還是委開？

Agent 需要查：
  1. 案例圖譜 → 找 3 個相似的自辦案例
                 找 3 個相似的委開案例

  2. 財務圖譜 → 對比成本、收益、時間

  3. 角色圖譜 → 自辦需要的能力（我有嗎？）
                 委開的建商信譽（他們可靠嗎？）

  4. 風險圖譜 → 自辦的風險
                 委開的風險

  5. 決策圖譜 → 過去類似決策的原因和結果

Agent 最後給出：
  「根據以上 5 層分析，我建議...
   理由是...
   風險是...」
```

**你的任務**：
- 確認 Agent 查對了 5 個圖譜嗎？
- 有沒有遺漏重要的層面？
- 如果加上「政治因素」（市府支持度），怎樣加入圖譜？
