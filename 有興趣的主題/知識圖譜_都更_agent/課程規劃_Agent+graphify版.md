# 台北市都市更新推廣課程規劃
## 融合 Agent 與 graphify 知識圖譜

**目標受眾**：一般民眾、地主、社區領導
**學期**：秋季班（16 週）
**教學模式**：講座 + 實作工坊 + 社區參訪
**核心創新**：用 AI Agent + 知識圖譜提高決策透明度

---

## 第一階段：基礎認識（週 1-4）

### 週 1-2：認識都市更新 × 你為什麼需要 Agent
**主題**：什麼是都市更新？為什麼決策這麼複雜？

- 1-1：都市更新 101（危老建築、更新條例、基本流程）
- 1-2：傳統決策流程的痛點
  - 信息不對稱（政府知道什麼、建商知道什麼、居民不知道什麼）
  - 各角色的目標不同（政府：核發建照、建商：利潤、居民：公平）
  - 溝通成本高（會議多、文件多、反覆確認）

- **Agent 如何幫助**：
  - 統一的信息中樞（所有人看到一致的進度）
  - 自動衝突檢測（新決策會不會違反法規或傷害誰）
  - 透明化決策支持（「為什麼這樣決定」有依據可查）

**實作**：你的社區/建案現在信息流動的問題在哪？

---

### 週 3-4：認識知識圖譜 × 如何用 graphify 看清複雜關係
**主題**：都市更新的 9 層知識圖譜

- 3-1：什麼是知識圖譜？
  - 不是流程圖，而是概念網絡
  - 例：法規 ↔ 角色 ↔ 進度 ↔ 成本

- 3-2：都市更新的 9 層知識圖譜（都更領航者 Agent 的大腦）
  ```
  ① 法規圖譜 (Legal-KG)
     └─ 都更條例、建築法規、防災法規

  ② 角色圖譜 (Role-KG)
     └─ 地主、建商、政府、居民、金融機構

  ③ 進度圖譜 (Progress-KG) ⭐ 核心
     └─ 規劃 → 送審 → 審核 → 建照 → 施工 → 竣工

  ④ 財務圖譜 (Fin-KG)
     └─ 融資進度、成本、利潤分配

  ⑤ 願景圖譜 (Vision-KG)
     └─ 建案的目標（防災、親子、綠建築等）

  ⑥ 風險圖譜 (Risk-KG)
     └─ 地震、資金短缺、利益衝突

  ⑦ 決策圖譜 (Decision-KG)
     └─ 決策歷程：為什麼選 A 而不是 B

  ⑧ 溝通圖譜 (Communication-KG)
     └─ 誰和誰說過什麼、什麼時候

  ⑨ 案例圖譜 (Case-KG)
     └─ 類似的歷史案例、學到的教訓
  ```

- 3-3：graphify 如何自動構建這些圖譜
  - 從文件、會議紀錄、進度報告自動提取
  - 識別概念間的聯繫
  - 生成可視化和分析報告

- **實作**：用 graphify 分析一個真實案例（Spreadsheet → 知識圖譜）

**這週的核心問題**：「我怎麼知道這個建案的風險在哪？」→ 查風險圖譜

## 第二階段：應用深化（週 5-10）

### 週 5：共同負擔 × 透明的成本分配
**主題**：成本為什麼這麼複雜？怎樣用 Agent 把它講清楚？

- 傳統方式：複雜的表單、難以理解的公式
- Agent + graphify 方式：
  - 財務圖譜可視化（每一塊錢去哪了）
  - 利益分配圖（地主拿多少、建商拿多少、誰吃虧了）
  - 自動對比：你的案子 vs. 類似案例

**實作工坊**：「我家值多少？」
- 輸入：地坪數、位置、目前實際帳戶資訊
- Agent 查詢：財務圖譜 + 案例圖譜
- 輸出：可理解的成本分配方案

---

### 週 6-7：查資料與問問題 × Agent 就是超級秘書
**主題**：從「問人不如問 Google」升級到「問 Agent」

**傳統痛點**：
- 找不到資訊（文件散亂）
- 問政府部門響應慢
- 各地信息不一致

**Agent 的能力**：
- **進度查詢**：「現在到哪一步了？」
  - Agent 執行：`query "進度圖譜 當前狀態"`
  - 回答：完成度、下一個里程碑、瓶頸

- **法規查詢**：「為什麼要這樣做？」
  - Agent 執行：`query "法規圖譜 ↔ 你的決定"`
  - 回答：相關法律條文、原因、例外情況

- **案例對標**：「有沒有類似的案子？怎麼做的？」
  - Agent 執行：`query "案例圖譜 類似案例"`
  - 回答：3-5 個相似案例、他們遇到的問題、解決方案

**實作工坊**：「你問，Agent 答」
- 用 Telegram 或表單提問
- Agent 自動查圖譜回答
- 記錄常見問題建立 FAQ 知識庫

---

### 週 8-9：社區如何做調查 × 用圖譜協調共識
**主題**：地主眾議紛紛，怎樣達成共識？

**傳統方式**：開會、投票、反覆協商 → 浪費時間
**用圖譜的方式**：

- **角色圖譜**：誰有發言權？
- **決策圖譜**：歷次決定是怎麼做的？
- **溝通圖譜**：誰和誰還沒好好談過？

**工作流程**：
1. 收集所有地主的想法 (問卷 + Agent)
2. graphify 自動構建「社區共識圖」
   - 哪些意見相同？
   - 哪些有衝突？
   - 衝突的根本原因是什麼？
3. 針對性協調（只討論真實的分歧，不浪費時間）

**實作工坊**：「社區投票透明化」
- 設計一份社區調查表
- 用 Agent 收集回應
- 用 graphify 生成共識地圖
- 識別需要重點溝通的議題

---

### 週 9：融資與信託 × 金流透明化
**主題**：錢怎麼流動的？銀行、地主、建商之間誰欠誰什麼？

- 財務圖譜的實際應用：
  - 融資進度（貸款批下來沒？）
  - 分期支付（什麼時候該付款？）
  - 風險監控（有沒有資金缺口？）

**實作**：用 Agent 做「融資進度儀表板」

---

### 週 10：不同開發模式 × 選哪一種最划算？
**主題**：自辦更新 vs. 委託開發商 vs. 合作開發，差別在哪？

**用圖譜的方式**：
- **決策圖譜**：過去類似案子選了什麼、結果如何？
- **財務圖譜**：不同模式的成本/收益比較
- **風險圖譜**：各模式的風險在哪？

**實作工坊**：「為你的案子選最優方案」
- 輸入案子特徵（地點、地主人數、預算）
- Agent 查案例圖譜找相似案例
- 推薦 3 種方案 + 成本對比

## 第三階段：實踐與體驗（週 11-16）

### 週 11：都更博覽會導覽 + Agent 實時查詢
**活動**：參與台北都更博覽會（9/20 左右）

**創新應用**：
- 用手機掃二維碼提問
- Agent 實時用圖譜回答（不是人類講師回答）
- 現場展示 graphify 可視化圖表

**參與者學到**：「原來 AI 也能幫忙理解這麼複雜的東西」

---

### 週 12：大直都更解壓縮館參訪 + 案例深度分析
**活動**：實地參訪（規劃中的展館或已完成案例）

**同步進行**：
- 現場記錄（照片、筆記）
- graphify 實時更新該案例的圖譜
- Agent 當場回答「為什麼這樣設計」

**學習成果**：
- 看到理論在實際案例中如何應用
- 理解建築設計和都市更新的關係

---

### 週 13：新科技在都市更新中的應用
**主題**：BIM、AI 建模、smart building

**分成 3 小模塊**：
- 13-1：磁磚新科技（馬可貝里講座）
- 13-2：BIM + AI 建模（Claude 3D 建模案例）
- 13-3：智慧建築與永續（綠建築、智能系統）

**Agent 的角色**：
- 將技術規格轉譯成「對地主的實際好處」
- 用圖譜對比不同技術選擇的成本效益

---

### 週 14：工程實踐 + 進度追蹤
**主題**：從紙面到實際施工

**內容**：
- 14-1：地下室開挖工程（安全風險、成本、進度）
- 14-2：工地三級管理與售後服務（為什麼重要）
- 14-3：工程進度如何用 graphify 追蹤

**實作**：
- 模擬一個施工項目
- 用進度圖譜追蹤完成度
- Agent 自動預警延誤

---

### 週 15：專家講座 + 案例沙龍
**邀請對象**：
- 地政士：法律合規（週 11 已邀約）
- 建商代表：開發模式、融資
- 居民代表：參與式更新經驗
- 政府代表：審批流程、政策

**獨特設置**：
- 有 Agent 即時回答技術問題
- 用圖譜展示各方立場的異同
- 記錄討論，實時更新知識圖譜

---

### 週 16：課程綜合討論 + 行動計畫
**主題**：「我接下來應該怎麼做？」

**三種參與者的行動計畫**：

1. **一般民眾**
   - 我的社區/建案適合哪種更新模式？
   - 怎樣參與決策過程？
   - 怎樣用 Agent 獲取可靠信息？

2. **地主**
   - 我家的房子值多少？
   - 共同負擔應該付多少？
   - 如何避免被坑？

3. **社區領袖/組織**
   - 怎樣組織地主共識？
   - 怎樣做有效的社區調查？
   - 怎樣和政府、建商有效溝通？

**課程產物**：
- 每個參與者寫下 1-2 個具體的後續行動
- 建立「課程校友群」持續互助
- 公開分享案例經驗（用圖譜記錄）

## 課程創新點

1. **技術 + 實踐結合**
   - 不是簡單的講座，而是「用工具解決真實問題」

2. **透明化決策**
   - 用知識圖譜讓所有人看到相同的信息
   - 減少信息不對稱導致的衝突

3. **持續學習**
   - 課程本身也是一個知識圖譜
   - 參與者在課程中提出的案例被記錄、分析、分享

4. **民眾友善**
   - Agent 會用簡單的語言解釋複雜概念
   - 圖表視覺化易於理解
   - 不需要技術背景
